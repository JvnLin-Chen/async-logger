# 工业级多线程异步日志库

## 版本状态：v2 - 底层 I/O 优化
- **v1**: 最小异步闭环（队列 + 单后台线程 + 基础停机），10000条测试通过。
- **v2**: 重构 `FileWriter`，**文件句柄保持常开**，支持跨天无缝切换，增加空指针及异常防御。

## v2 验收结果
| 测试项 | 结果 |
|---|---|
| Test1 单线程 10000 条 | 耗时 74~91ms，文件恰好 10000 行 |
| Test2 4 线程各 2500 条 | 文件 10000 行，每线程各 2500 条，无丢失无粘行 |
| 异常测试（断盘/无权限） | 后台线程不崩溃，控制台输出 Error 提示，丢弃当前日志 |

## v2 关键设计决策
1. **文件常开**：`FileWriter` 内部维护 `FILE* file`，不用每次写入都 `fopen`/`fclose`，大幅提升后台写盘吞吐量。
2. **跨天切换逻辑（核心）**：采用“**先开新文件，成功后再关旧文件**”的策略。若新文件打开失败，保留旧文件句柄继续写，防止跨天瞬间因权限/磁盘问题导致日志全丢。
3. **防御性编程**：所有 `fclose` 前必查 `file != nullptr`；`addLog` 写文件前必查指针是否为空，杜绝后台线程因空指针崩溃。

## v2 踩坑记录
- **坑1（野指针）**：`FILE* newFile;` 未初始化，直接传给 `fopen_s`，若打开失败会导致野指针。
- **坑2（Double Free）**：跨天逻辑中，如果先 `fclose(file)` 然后新文件打开失败，再次 `return` 或后续 `fclose`，会对同一个空句柄重复关闭导致程序崩溃。
- **坑3（逻辑一票否决）**：`addLog` 开头直接 `if (file == nullptr) return;` 会导致如果一开始没打开文件，后续即使环境恢复也无法重试写入了。

## 遗留问题（-> v3 计划）
1. 无界队列（`std::queue`）：如果磁盘写入速度持续慢于产生速度，内存会 OOM。
2. 下一步引入**有界队列**与**溢出策略**（如阻断/丢弃最旧），加入丢弃计数器监控。
